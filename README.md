# Mentor Style Lab

这是一个在本机运行的论文写作练习工具，用来学习指定学者的写法，并比较改写效果。

上传你想学习的学者的英文论文，选出值得学习的段落，整理成文风卡，再用它修改自己的稿件。最后把原文、普通润色和按文风卡改写的版本匿名排在一起，交给熟悉这位学者的人评价。

每位学者都有独立项目。论文和改写记录保存在本机，不随 Git 上传。分析和改写使用你已有的聊天模型：下载任务材料、交给模型、把结果带回来即可，无需配置模型 API。

这里的“蒸馏”指从文章中提炼写作规则和例子。目前没有训练模型参数，也不保证每次改写都能复现某个人的文风。

## 先跑起来

需要 Python 3.11 或更新版本。下载仓库后，进入项目文件夹。

Windows PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-ui.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

macOS / Linux：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-ui.txt
.venv/bin/python -m streamlit run app.py
```

在浏览器打开 <http://127.0.0.1:8501>。程序默认只接受本机访问，没有公共上传站点或多人账户系统。

## 怎么用

**1. 建项目，上传论文。** 填目标学者姓名或代号。先挑几篇自己熟悉的代表作；独作和已确认执笔的文章更容易判断。目标学者的学习材料、其他作者的领域对照、试改材料和最终测试材料分别登记。

**2. 对着原页选段。** 页面同时显示 PDF 和抽取文字。选择摘要、引言、方法或其他章节，复制完整段落，核对页码、阅读顺序和署名后保存。两栏 PDF 可能抽乱顺序，扫描件需要先做 OCR。

**3. 整理自己的文风卡。** 下载学习包，交给聊天模型。模型会返回带原文证据的 JSON 规则，粘贴回页面即可检查和保存。例如，一条规则可以描述贡献段怎样衔接文献遗漏与本文工作，同时注明哪些文章支持、哪些情况不适用。没有证据的章节可以以后再补。

**4. 改一段自己的文章。** 粘贴待改原文，列出不能改动的研究信息。程序会导出普通润色和文风改写两份任务包。建议各开一个新对话，分别生成；普通润色的对话不读文风卡。

**5. 做三版盲评。** 核对两份改写没有遗漏、增加或改变研究含义后，把英文正文粘贴回来。程序生成匿名评阅稿和单独的答案文件。只把匿名稿交给评阅人，先收评分再揭盲。匿名稿为 HTML，可直接阅读或通过浏览器打印为 PDF。

第一次可以只试一个摘要。先看事实有没有改错，再看是否更像，以及是否更好读；并列或分不出来都应记录。

## 文件放在哪里

```text
local/projects/你的项目代号/
  project.json        学者与项目设置
  papers/             上传的 PDF
  excerpts.json       已核对的选段
  profiles/           每次保存的文风卡
  tasks/              原文、主张清单与两份改写任务包
  reviews/            各轮匿名稿、答案与校验记录
```

`local/` 已被 Git 忽略。换电脑前请另行备份这个文件夹；只克隆仓库不会带回你的论文和文风卡。学习包包含原文选段，发送给聊天模型前，请确认你可以将这些材料提供给该服务。

旧版命令行工具仍可使用，不会自动搬动已有资料：

```bash
python stylelab.py ingest --source "你的PDF文件夹"
python stylelab.py profile --excerpts local/curated/excerpts.jsonl
```

更多命令和数据格式见[命令行工作流程](docs/selected-corpus-workflow.md)。

## 现在能做到什么

程序负责资料分开保存、PDF 读取、重复文件检查、选段出处核对、文风卡版本记录和匿名稿导出。它会拦下错误引文、其他项目的选段、把评估材料放进文风卡等问题。

写作习惯是否解释得对、改写是否保持研究含义、是否真的接近目标学者，仍需要阅读和评阅。引文匹配只是证明引用来自原文；数字一致也不能证明比较对象、因果强度和结论没变。合著者、学科和期刊的共同写法都可能影响判断。

同文版本目前按文件内容和相近文件名检查。标题完全不同的版本、扫描文本、自动章节识别还需要人工处理。网页主要用于个人在本机操作，同一项目暂不支持多人同时编辑。

## 维护与贡献

修改代码后运行测试：

```bash
python -m unittest discover -s tests -v
```

请先安装 `requirements-ui.txt`，并使用安装依赖的同一个 Python 环境。测试用虚构材料，不包含任何人的论文或文风卡。提交改动时检查暂存文件，只同步代码、模板和通用文档。

文档编辑可参考 [humanizer-zh](https://github.com/syw2039/humanizer-zh)：去掉空话和模板腔，保留事实与原意。它是可选的写作技能，不是运行依赖，也不用于判断文本是否由 AI 生成。[安装与使用说明](docs/writing-skill.md)

想了解评阅设计，可以继续读[评价方法](docs/evaluation.md)、[独立 AI 评阅](docs/ai-review-iteration.md)和[评阅者校准](docs/reviewer-calibration.md)。版本变化见 [CHANGELOG](CHANGELOG.md)。
