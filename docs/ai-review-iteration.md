# AI 评阅驱动的开发迭代

用途是发现改写问题、检验一条具体修订是否有帮助。AI 评分不是导师评价，不是个人文风识别准确率，也不是参数训练。规则、英文候选、来源、评分及揭盲答案存入忽略同步的 `local/`；临时评阅目录同样不得加入版本控制。

## 规则更新的证据等级

- 原文观察：能追溯到已核对的学习集页面；记录作品数量、作者角色及反例。
- 编辑约束：数字、引用、基准、因果强度、限定词与原意的忠实要求；不得称为作者特征。
- 开发反馈：某个评阅者对固定片段的判断；可提出下一轮假设，不增加原文支持篇数。

完整摘要、引言研究缺口、贡献、方法、结果、解释、局限分别选择规则。不能因为某摘要任务先行表现好，就要求引言选段先列全套任务。不要强制贡献数量、段落数量、连接词或字数。

## 冻结后再评

1. 保存规则版本、完整选段、逐项命题、生成条件及输入哈希。命题包括首创、唯一性、因果断言、政策预期，不只列样本和数字。
2. 提供认真制作的通用学术润色对照。区分重用的诊断片段、新选段、新论文和真正冻结的留出集。来自同一论文的新段落不能叫独立留出论文。
3. 为每位评阅者随机编号并改变呈现顺序；答案在管理员目录。不同编号的文本须哈希一致。
4. 干净评阅使用新对话，不 fork 或发送历史评分。旧对话可另做复评，但需声明已见内容。用户须先明确授权创建/联系这些对话。
5. 预先写出采用门槛：事实错误不能用风格高分抵销；打平不能解释为优于对照；不一致和退步必须报告。固定次数，不边看结果边改候选追分。

## 两阶段协议

第一阶段只提供匿名候选、章节功能及目标/领域参考。分别评文风接近度、组织、自然度、清晰度；要求具体候选及参考短引文，允许打平、低把握和无法区分。保存评分及 SHA256 后冻结。

第二阶段提供完整原文与命题索引。逐项检查保留、遗漏、新增、加强、削弱及不确定；原文已有表述风险另列。不要把简化清单未记载的原文主张误称为改写新增，不把主动弱化默认为无损改写。不能用原文审核反向修改已经保存的文风评分。

## 揭盲审计与解释

核对评分覆盖所有候选、每条命题有记录、引用逐字存在、排名编号有效、输入哈希及阶段一哈希未变、历史结果未被覆盖。程序只能验证这些结构和溯源条件，不能验证评论解释正确；负责人仍应检查实质意见。

分别报告干净评阅与旧对话复评；展示逐组结果而非合成一个“成功率”。同模型的两个对话不是独立人类样本；相同学习参考同时用于生成和评价会限制外部有效性。缺少同体裁领域对照、作者实际执笔未确认、片段来自共同合作者等限制均须保留。

揭盲后可采用有依据的规则修复；未获优势或评阅分歧的规则保持暂定。若修正文稿，另存版本，不能把未重新评阅的修正版称为原盲评通过。后续在未见论文上冻结评测，并用导师反馈校准。
